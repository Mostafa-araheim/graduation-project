1. HIGH-LEVEL PROJECT OVERVIEW
================================================================================

The Pharma application is a backend API service designed to help pharmacies in
Egypt manage their operations and allow customers to:
  • Browse available medications from multiple pharmacies
  • Check medication availability and pricing
  • Place orders for delivery
  • Rate and review pharmacies
  • For owners: Manage pharmacy details and inventory
  • For admins: Monitor system operations (not yet built)

The application is BACKEND-ONLY (REST API) with no frontend components.
Intended to be consumed by web, mobile, or third-party applications.

5. IMPLEMENTED APIs AND THEIR PURPOSES
================================================================================

5.1 PHARMACY MANAGEMENT API
    Base URL: /api/v1/pharmacies

    PUBLIC ENDPOINTS:
    ─────────────────────────────────────────────────────────────────
    GET    /locations
           Returns all pharmacies with basic info (name, location, hours)

    GET    ?name=X&minRating=Y&isOpen=Z&latitude=A&longitude=B&page=N&size=M
           Search pharmacies with filters:
           - Text search by name
           - Minimum rating filter (0-5)
           - Open/closed status
           - Distance-based ordering
           Returns paginated list of PharmacyDto

    GET    /{pharmacyId}
           Get detailed pharmacy info:
           - Full address details
           - Product categories available
           - Recent reviews and ratings
           Returns PharmacyInfo object

    GET    /{pharmacyId}/{categoryId}
           Get products in pharmacy under specific category
           Returns paginated PharmacyProductDto list

    POST   /rating
           Submit rating for pharmacy (1-5 stars)
           Requires ROLE_CUSTOMER
           Updates average rating and rating count

    POST   /review
           Submit text review for pharmacy
           Requires ROLE_CUSTOMER
           Includes reviewer name and comment

    POST   /bulk
           Bulk create multiple pharmacies (data seeding)
           Used for loading test data

    OWNER ENDPOINTS (requires ROLE_OWNER):
    ─────────────────────────────────────────────────────────────────
    POST   /
           Create new pharmacy
           Required fields: name, address, location, hours
           Automatically creates associated Inventory
           Returns created PharmacyDto

    DELETE /{pharmacyId}
           Delete pharmacy (validates owner access)
           Cascading delete of related data

    PATCH  /{pharmacyId}
           Partial update of pharmacy details
           Supported updates: name, image, hours, address, location
           Geometry auto-updated from coordinates

    GET    /owner
           Get all pharmacies owned by authenticated user
           Returns list of PharmacyDto

    GET    /owner/{pharmacyId}
           Get specific pharmacy with ownership validation
           Returns PharmacyDto


5.2 PHARMACY PRODUCT API
    Base URL: /api/v1/pharmacy-products (not yet exposed as full CRUD)

    PARTIALLY IMPLEMENTED:

    - Returns paginated list with distance calculations

    NOT YET IMPLEMENTED:

5.3 AUTHENTICATION API
    Base URL: /api/v1/auth

    SIGNUP FLOW:
    ─────────────────────────────────────────────────────────────────
    POST   /signup/start
           Initiate signup process
           Body: { email, name, role (CUSTOMER|OWNER|PHARMACIST) }
           Returns: { signupId }
           Action: Sends verification code to email

    POST   /signup/verify
           Complete signup with verification code
           Body: { signupId, code }
           Returns: User object with profile created
           Validation: Max 3 attempts, 3-minute TTL

    LOGIN FLOW:
    ─────────────────────────────────────────────────────────────────
    POST   /login/start
           Initiate login process
           Body: { email, role }
           Returns: { loginId }
           Action: Sends verification code to email

    POST   /login/verify
           Complete login with verification code
           Body: { loginId, code }
           Returns: JWT token + user info
           Validation: Max 3 attempts, 3-minute TTL


5.4 CART & CHECKOUT API
    Base URL: /api/v1/carts

    OPERATIONS:
    ─────────────────────────────────────────────────────────────────
    POST   /
           Create new cart
           Requires ROLE_CUSTOMER

    GET    /{cartId}
           Retrieve specific cart
           Ownership validation

    GET    /user
           Get all carts for logged-in user

    POST   /{cartId}/items
           Add item to cart

    PATCH  /{cartId}/items/quantity
           Update item quantity

    POST   /{cartId}/items/increase
           Increase item quantity by 1

    DELETE /{cartId}/items/{productId}
           Remove item from cart

    POST   /{cartId}/checkout
           Process checkout with Stripe payment
           Updates inventory, creates order

    See entire_code_related_to_cart_and_order.txt for full details

════════════════════════════════════════════════════════════════════

STEP 1: SIGNUP/AUTHENTICATION

├─ owner_profile
├─ customer_profile
└─ pharmacist_profile

PHARMACY MANAGEMENT:
────────────────────────────────────────────────────────────────────
pharmacy (main table)
├─ pharmacy_id (PK)
├─ owner_user_id (FK to owner_profile.user_id, nullable)
├─ name
├─ image_url
├─ location (PostGIS geometry/Point, SRID 4326)
├─ latitude, longitude (for easier access)
├─ opening_time, closing_time (LocalTime)
├─ is_24_hours (Boolean)
├─ average_rating (BigDecimal 0-5)
├─ rating_count, review_count
└─ created_at

pharmacy_address (1:1, orphan removal)
├─ pharmacy_id (PK/FK)
├─ street, city, postal_code, country
└─ apartment_number

INVENTORY SYSTEM:
────────────────────────────────────────────────────────────────────
inventory (1:1 with pharmacy, orphan removal)
├─ pharmacy_id (PK/FK)
└─ relationship to pharmacy_product (1:M)

pharmacy_product (products in pharmacy)
├─ pharmacy_product_id (PK)
├─ pharmacy_id (FK)
├─ inventory_pharmacy_id (FK, references inventory.pharmacy_id)
├─ product_id (FK to product catalog)
├─ price (BigDecimal)
├─ quantity (Integer)
├─ availability_status (Available|OutOfStock|LimitedSupply)
└─ unique constraint: (inventory_pharmacy_id, product_id)

Auto-updates on stock depletion:
  quantity -= ordered_quantity
  IF quantity <= 0: status = OutOfStock
  ELSE: status = Available

RATINGS & REVIEWS:
────────────────────────────────────────────────────────────────────
pharmacy_rating
├─ rating_id (PK)
├─ pharmacy_id (FK)
├─ customer_user_id (FK to customer_profile.user_id)

└─ created_at

pharmacy_review
├─ review_id (PK)

├─ customer_user_id (FK)

└─ created_at

STAFF MANAGEMENT:

pharmacy_staff (composite PK: pharmacy_id + user_id)

FLOW EXAMPLE - CREATING PHARMACY:
════════════════════════════════════════════════════════════════════
1. Owner calls: POST /api/v1/pharmacies
   Send CreatePharmacyRequest with all details

2. PharmacyOwnerService.createPharmacy():
   a. Fetch OwnerProfile by userId
   b. Map CreatePharmacyRequest → Pharmacy entity
   c. Set owner relationship
   d. Create PharmacyAddress from request
   e. Create Inventory (empty, no products yet)
   f. PrePersist: Calculate geometry from lat/lon
   g. Save all to database (cascading)

3. Database transactions:
   INSERT INTO pharmacy (name, image_url, owner_user_id, ...)
   INSERT INTO pharmacy_address (pharmacy_id, street, city, ...)
   INSERT INTO inventory (pharmacy_id)
   UPDATE pharmacy SET location = ST_GeomFromText(...)

4. Return PharmacyDto to client

FLOW EXAMPLE - CUSTOMER SEARCHING:
════════════════════════════════════════════════════════════════════
1. Customer calls: GET /api/v1/pharmacies?name=noor&minRating=4&isOpen=true&latitude=30&longitude=31

2. PharmacyService.getPharmacies():
   a. Build JPA Specification combining:
      - hasName("noor"): LIKE query
      - hasMinRating(4.0): >= comparison
      - isOpenNow(true): Complex time logic
      - orderByDistance(30, 31): ST_Distance sorting

   b. Execute: pharmacyRepository.findAll(spec, pageable)

   c. Get distances via locationService for all results:
      - Extract coordinates from results
      - Call distance API
      - Get list of distances back

   d. Map to PharmacyDto, include distances

   e. Return PageResponse with total elements

3. Database query (simplified):
   SELECT p.* FROM pharmacy p
   WHERE p.name LIKE '%noor%'
   AND p.average_rating >= 4.0
   AND (p.is_24_hours = true OR (p.opening_time <= NOW() AND p.closing_time >= NOW()))
   ORDER BY ST_Distance(p.location, ST_Point(31, 30))
   LIMIT 10

FLOW EXAMPLE - CHECKOUT:
════════════════════════════════════════════════════════════════════
1. Customer calls: POST /api/v1/carts/{cartId}/checkout

2. CheckoutService.checkout():

      - DELETE FROM cart_item
      - Return order confirmation

3. Database transactions:
   BEGIN TRANSACTION
   SELECT pharmacy_product WHERE pharmacy_product_id = X FOR UPDATE
   UPDATE pharmacy_product SET quantity = quantity - N WHERE ...
   INSERT INTO order (...)
   INSERT INTO order_item (...)
   DELETE FROM cart_item (...)
   COMMIT

9. AUTHENTICATION AND AUTHORIZATION STATUS
================================================================================

IMPLEMENTED AUTHENTICATION METHODS:
────────────────────────────────────────────────────────────────────
✅ Email-OTP (One-Time Password) Verification
   - No password system (uses email verification codes)
   - 8-digit random code generated
   - Code hashed with SHA-256
   - Stored in Redis with 3-minute TTL
   - Max 3 verification attempts
   - Attempt counter incremented with each try

✅ JWT Token Support
   - JJWT library (v0.12.6)
   - Generated after successful OTP verification
   - Contains user info as claims
   - Included in Authorization header: "Bearer {token}"
   - Validated on protected endpoints

✅ Session Management
   - Redis-backed session storage
   - SessionId + SignupSession/LoginSession object
   - Time-based expiration (3 minutes)
   - Automatic cleanup on expiry

AUTHORIZATION (Access Control):
────────────────────────────────────────────────────────────────────
✅ Role-Based Access Control (RBAC)
   Four roles defined:
   - ROLE_CUSTOMER: Can browse, rate, review, purchase
   - ROLE_OWNER: Can manage pharmacies and staff
   - ROLE_PHARMACIST: Can verify prescriptions, manage staff inventory
   - ROLE_ADMIN: Can manage system (not yet implemented)

✅ Multiple Roles Per User
   - Each user has Set<UserRole>
   - Can have multiple roles simultaneously
   - Login requires specifying which role to use

✅ Spring Security Integration
   - @PreAuthorize("hasRole('OWNER')") on controller methods
   - AuthenticationPrincipal injection
   - Automatic 403 Forbidden on unauthorized access

✅ Resource-Level Access Validation
   - PharmacyOwnerService validates user owns pharmacy before allowing edits
   - Prevents cross-user pharmacy tampering
   - Similar validation planned for other resources

SECURITY MECHANISMS:
────────────────────────────────────────────────────────────────────
✅ Code Hashing
   - OTP codes hashed with SHA-256
   - Comparison: sha256(provided) == stored_hash
   - Time-constant comparison preferred (implement if high-security)

✅ Rate Limiting
   - Max 3 OTP verification attempts
   - Automatic session invalidation after 3 failed attempts
   - TTL enforcement (3 minutes)

✅ Email Verification
   - Email uniqueness check on signup
   - User must verify email before account activation
   - Prevents automated account creation

✅ HTTPS Ready
   - All endpoints accept HTTPS
   - Spring Security can enforce HTTPS (configure in config)

MISSING SECURITY FEATURES:
────────────────────────────────────────────────────────────────────
❌ Password-based authentication
❌ Multi-factor authentication (beyond OTP)
❌ Account lockout policy (temporary after X failed attempts)
❌ Audit logging (track who accessed what when)

CORE BUSINESS LOGIC:
────────────────────────────────────────────────────────────────────
✅ Pharmacy Rating Calculation
   Algorithm:
     newAverage = (oldAverage * oldCount + newRating) / (oldCount + 1)
   Implementation: PharmacyService.updatePharmacyRating()
   Features:
   - Incremental calculation (efficient)
   - 2 decimal place precision
   - Handles null initial values (zero)

✅ Pharmacy Open/Closed Logic
   Implementation: Pharmacy.isOpen() / isClosed()
   Logic:
   - IF is_24Hours = true → always open
   - IF opening_time is null → closed
   - IF opening_time < closing_time (normal hours):
     * open = (currentTime >= opening_time) AND (currentTime <= closing_time)
   - IF opening_time > closing_time (overnight hours):
     * open = (currentTime >= opening_time) OR (currentTime <= closing_time)

✅ Stock Management Logic
   Implementation: PharmacyProductRepository.decrementStockIfEnough()
   SQL Query:
     UPDATE pharmacy_product
     SET quantity = quantity - requestedQty,
         availabilityStatus = CASE
           WHEN (quantity - requestedQty) > 0 THEN 'Available'
           ELSE 'OutOfStock'
         END
     WHERE pharmacy_id = ? AND product_id = ? AND quantity >= requestedQty

   Features:
   - Atomic at database level
   - Returns number of rows updated (0 if insufficient stock)
   - Prevents over-selling

✅ Distance Calculation
   Implementation: LocationService.getRoadDistances()
   Input: user location + list of target locations
   Output: List of distances in meters/kilometers
   Algorithm: External API call (road routing service)

✅ Geospatial Location Ordering
   Implementation: PharmacySpecifications.orderByDistance()
   Database function: ST_Distance(geometry_col, ST_Point(lon, lat))
   Orders results by distance ascending
   Used in pharmacy search
