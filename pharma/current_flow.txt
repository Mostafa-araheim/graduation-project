1. HIGH-LEVEL PROJECT OVERVIEW
================================================================================

Project Name: Pharma - Pharmacy Management & E-Commerce Platform
Description: A graduation project designed to help pharmacies in Egypt list
             available medications, allow consumers to check availability and
             prices, and provide AI-powered features for inventory management,
             demand prediction, and surplus medicine redistribution.

Technology Stack:
  - Backend: Spring Boot 4.0.2 (Java 25)
  - Database: PostgreSQL with PostGIS extension for geospatial queries
  - Caching: Redis (session storage + cart data)
  - Authentication: JWT (jjwt-api 0.12.6) with email-based OTP
  - External APIs: OpenRouteService (ORS) for routing/distance calculations
  - Mapping: MapStruct 1.6.3 for entity-to-DTO conversions
  - Validation: Jakarta Validation (JSR 380)
  - Web Framework: Spring MVC + Spring WebFlux (WebClient)
  - Security: Spring Security with CORS support
  - Mail: Gmail SMTP for email notifications
  - Build: Maven 3.x

Target Users/Roles:
  - ROLE_CUSTOMER: End consumers purchasing medications
  - ROLE_OWNER: Pharmacy owners/managers
  - ROLE_PHARMACIST: Pharmacy staff members
  - ROLE_ADMIN: System administrators

Frontend: Angular (referenced at http://localhost:4200 in CORS config)
Database: PostgreSQL (localhost:5432/Pharma)
Redis: localhost:6379
OpenRouteService API: https://api.openrouteservice.org

================================================================================

DEPLOYMENT MODEL: Monolithic Spring Boot REST API

CORE LAYERS:
  1. Controller Layer (7 controllers organized by domain)
     - auth/ → AuthSignupController, AuthLoginController
     - cart/ → CartController (14 endpoints for CRUD)
     - category/ → CategoryController
     - product/ → ProductController
     - pharmacy/ → PharmacyController
     - prescription/ → PrescriptionController (stub)

  2. Service Layer (17 services, mix of complete/stub)
     - Core: UserService, ProductService, PharmacyService, CartService, CategoryService
     - Checkout: CheckoutService (Order & Payment processing) [NEW]
     - Authentication: AuthSignupService, AuthLoginService
     - Location: LocationService (ORS API)
     - Incomplete: PrescriptionService, NotificationService, SalesService,
       SearchService, DonationService, AIService

  3. Repository Layer (JPA + Redis)
     - ProductRepository, PharmacyRepository, UserRepository, OrderRepository
     - CartRepository (interface) + CartRedisRepository (Redis implementation)
     - JPA Specifications: ProductSpecification, PharmacySpecifications

  4. Entity/Model Layer (37 entities across 6 domains)
     - Core: User, UserRole, CustomerProfile, OwnerProfile, PharmacistProfile
     - Catalog: Product, Category, Brand, DosageForm
     - Pharmacy: Pharmacy, PharmacyAddress, PharmacyStaff
     - Inventory: Inventory, PharmacyProduct, AvailabilityStatus
     - Order: Order, OrderItem, OrderStatus, DeliveryType, Payment, PaymentStatus
     - Reviews: PharmacyRating, PharmacyReview, SellerRating
     - P2P: P2PListing, P2PTransaction, Prescription, Notification, Invoice

  5. DTO Layer (Request/Response objects with validation)
     - Record-based DTOs organized by domain
     - Jakarta @NotNull, @NotEmpty, @Size validation annotations

  6. Mapper Layer (MapStruct interfaces)
     - CartItemMapper, CartMetadataMapper, ProductMapper, PharmacyMapper

  7. Exception Layer (Custom exception hierarchy + GlobalExceptionHandler)
     - BaseException → EntityNotFoundException, ValidationException, etc.

  8. Security Layer (JWT + Authentication)
     - AuthenticatedUser principal, JwtService, JwtValidatorFilter

INFRASTRUCTURE:
  - Redis: Carts (7-day TTL), Auth sessions (3-min TTL)
  - PostgreSQL: Primary data with PostGIS extension
  - OpenRouteService API: Distance matrix and isochrones
  - Gmail SMTP: OTP code distribution
  - WebClient: Async HTTP for ORS and AI service

5. IMPLEMENTED APIs AND THEIR PURPOSES
================================================================================

AUTHENTICATION & AUTHORIZATION
=====================================

POST /api/v1/auth/signup/start
  Purpose: Initiate user registration
  Request: { email, name, role: "ROLE_CUSTOMER" | "ROLE_OWNER" | "ROLE_PHARMACIST" }
  Response: { signupId, message: "Verification code sent" }
  Process: Generates 8-digit code, SHA256 hashes it, stores in Redis (3 min TTL), sends via email

POST /api/v1/auth/signup/verify
  Purpose: Complete signup by verifying email code
  Request: { signupId, code: "12345678" }
  Response: 200 OK with Authorization: Bearer {jwt}
  Process: Validates code, creates User + role-specific profile, generates 24hr JWT

POST /api/v1/auth/login/start
  Purpose: Initiate login process
  Request: { email, role }
  Response: { loginId, message: "Verification code sent" }

POST /api/v1/auth/login/verify
  Purpose: Complete login by verifying code
  Request: { loginId, code: "12345678" }
  Response: 200 OK with Authorization: Bearer {jwt}

PRODUCTS & CATALOG
=====================================

GET /api/Products
  Purpose: Search products with advanced filtering and sorting
  Query: categoryName, minPrice, maxPrice, pharmacyId, userLatitude, userLongitude, maxDistanceKm, sort, sortDirection
  Response: List<ProductResponse> with distances calculated via ORS API
  Validation: minPrice ≤ maxPrice, maxDistanceKm ≥ 0, latitude/longitude required for distance filter
  Sort Fields: price, name, stockQuantity, category

PHARMACY MANAGEMENT
=====================================

GET /api/v1/pharmacies/locations
  Purpose: Get all pharmacies for map display
  Response: List<PharmacyLocationResponse> with coordinates

GET /api/v1/pharmacies
  Purpose: Search pharmacies with filters (pagination)
  Query: name, minRating, isOpen, latitude, longitude, page, size
  Response: Page<PharmacyDto> (paginated, default size 10)

GET /api/v1/pharmacies/{pharmacyId}
  Purpose: Get detailed pharmacy information

GET /api/v1/pharmacies/{pharmacyId}/{categoryId}
  Purpose: Get products in pharmacy for specific category
  Response: Page<ProductResponse> (paginated)

POST /api/v1/pharmacies/rating
  Purpose: Rate a pharmacy
  Auth: ROLE_CUSTOMER
  Request: { pharmacyId, rating: 1-5 }
  Side Effects: Updates pharmacy.average_rating and rating_count

POST /api/v1/pharmacies/review
  Purpose: Add written review
  Auth: ROLE_CUSTOMER
  Request: { pharmacyId, comment: "..." }

POST /api/v1/pharmacies
  Purpose: Create new pharmacy
  Auth: ROLE_OWNER

CATEGORIES
=====================================

GET /api/v1/categories
  Purpose: List all product categories
  Response: List<CategoryDto>

POST /api/v1/categories
  Purpose: Create categories (bulk)
  Request: List<{ categoryName, imageUrl }>

SHOPPING CART (Redis-backed, 7-day TTL)
=====================================

POST /api/v1/carts
  Purpose: Create new cart
  Auth: ROLE_CUSTOMER
  Request: { name }
  Response: CartResponse with cartId

GET /api/v1/carts/{cartId}
  Purpose: Get cart contents
  Auth: ROLE_CUSTOMER
  Response: CartResponse with items, totals

GET /api/v1/carts/user
  Purpose: Get all user's carts
  Auth: ROLE_CUSTOMER

POST /api/v1/carts/{cartId}/items
  Purpose: Add item to cart
  Auth: ROLE_CUSTOMER
  Request: { inventoryRecordId }
  Validation: Item in stock, same pharmacy as other items

PATCH /api/v1/carts/{cartId}/items/quantity
  Purpose: Set specific quantity
  Request: { inventoryRecordId, quantity }

POST /api/v1/carts/{cartId}/items/increase
  Purpose: Increase quantity by 1

POST /api/v1/carts/{cartId}/items/decrease
  Purpose: Decrease quantity by 1 (removes if reaches 0)

DELETE /api/v1/carts/{cartId}/items
  Purpose: Remove item from cart

DELETE /api/v1/carts/{cartId}/clear
  Purpose: Remove all items (keep cart)

DELETE /api/v1/carts/{cartId}
  Purpose: Delete entire cart

POST /api/v1/carts/assign
  Purpose: Create and populate cart in one call
  Request: { cartName, items: [{ inventoryRecordId, quantity }] }

POST /api/v1/carts/{cartId}/checkout [NEW]
  Purpose: Convert cart to order
  Auth: ROLE_CUSTOMER
  Request: { deliveryType: "DELIVERY"|"PICKUP", paymentMethod: "CARD"|"CASH", deliveryAddress }
  Response: CheckoutResponse with orderId
  Process: Creates Order, OrderItems, Payment, decrements stock, clears cart

8. DATA MODELS / SCHEMA / DATABASE FLOW
================================================================================

DATABASE: PostgreSQL with PostGIS
TABLES: 19 core tables + indexes

USER ENTITIES:
  - User: id, email, name, phone, created_at, roles
  - UserRole: ROLE_CUSTOMER, ROLE_OWNER, ROLE_PHARMACIST, ROLE_ADMIN
  - CustomerProfile, OwnerProfile, PharmacistProfile: 1:1 with User
  - UserAddress: street, city, country, postal_code

CATALOG:
  - Category: id, name, image
  - Brand: id, name, image
  - Product: id, name, description, dosage_form, strength, requires_prescription

PHARMACY:
  - Pharmacy: id, name, location (PostGIS Point), hours, rating, reviews
  - PharmacyAddress: id, pharmacy_id, address fields
  - PharmacyStaff: composite PK (pharmacy_id, pharmacist_id)

INVENTORY:
  - Inventory: id, pharmacy_id (unique) - one per pharmacy
  - PharmacyProduct: id, inventory_id, product_id, price, quantity, availability_status

ORDERS:
  - Order: id, customer_id, pharmacy_id, total_amount, status, delivery_type, payment_method
  - OrderItem: id, order_id, product_id, quantity, price
  - Payment: id, order_id, amount, status, provider_payment_intent_id

REVIEWS:
  - PharmacyRating: id, customer_id, pharmacy_id, rating (1-5)
  - PharmacyReview: id, customer_id, pharmacy_id, comment
  - SellerRating: id, buyer_id, seller_id, rating (1-5), comment

OTHER:
  - P2PListing, P2PTransaction, Prescription, Notification, MedicationReminder, Invoice

REDIS STORAGE:
  - "user:{userId}:carts" (SET) → cart IDs
  - "cart:{cartId}" (HASH) → metadata (userId, name, createdAt, updatedAt)
  - "cart:{cartId}:items" (HASH) → items (field: inventoryRecordId, value: CartItem)
  - "auth:signup:{signupId}" (STRING) → SignupSession (3 min TTL)
  - "auth:login:{loginId}" (STRING) → LoginSession (3 min TTL)

12. VALIDATION, ERROR HANDLING, LOADING STATES, AND FALLBACK BEHAVIOR
================================================================================

VALIDATION:
  - Jakarta @Valid, @NotNull, @NotEmpty, @Positive, @Size annotations
  - Custom: ProductService.validateFilter(), validateSort()
  - Custom: CartService.validateCartAccess(), validateSamePharmacy()

ERROR HANDLING:
  - Global exception handler with standardized responses
  - Custom exceptions: EntityNotFoundException (404), ValidationException (400),
    BusinessRuleViolationException (400), AccessDeniedException (403)
  - ErrorResponse: { errorCode, message, status, timestamp, path }
  - ApiResponse wrapper: { success, message, data, error, timestamp }

FALLBACK BEHAVIOR:
  - ORS unavailable: RuntimeException (no retry, no fallback)
  - Email send fails: Exception bubbles up (no fallback)
  - Item out of stock: BusinessRuleViolationException
  - Cart expired: EntityNotFoundException
  - Limited graceful degradation
